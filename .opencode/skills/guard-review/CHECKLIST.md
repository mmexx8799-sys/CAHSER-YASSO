# Production Checklist — تفاصيل قابلة للتحديث

هذا الملف منفصل عن SKILL.md عمدًا — عشان تقدر تضيف/تعدّل بنود من غير ما تلمس منطق الـ Skill نفسه.

## أ. بوابات ميكانيكية (لازم 100%، بدون تقدير شخصي)
- [ ] `tsc --noEmit` بدون أخطاء
- [ ] `npm run build` ينجح
- [ ] كل الـ tests الموجودة تعدي (لو فيه tests)
- [ ] `git diff --stat` يطابق تمامًا قائمة allowed-files في الـ REQ
- [ ] مفيش `console.log` / `debugger` مسيبين في الكود الجديد
- [ ] مفيش secrets / API keys / tokens ظاهرة في الكود أو الـ diff

## ب. أمان
- [ ] أي تعديل في `firestore.rules` له تعديل مقابل في الكود يستخدمه (والعكس)
- [ ] لو `firestore.rules` اتغيرت: **وقف واطلب تأكيد صريح** إن `firebase deploy --only firestore:rules` اتنفذ فعلًا — لا تفترض
- [ ] أي route/action جديد له RBAC check واضح (مش معتمد على الـ UI بس)
- [ ] أي قيمة سعر/مبلغ جايه من الـ client تتفحص ضد قيمة مرجعية من السيرفر (مش تُقبل كما هي)
- [ ] مفيش بيانات حساسة (رقم هاتف، عنوان، بيانات دفع) بتتسرب في الـ logs أو الـ error messages

## ج. سلامة البيانات (Transactions)
- [ ] أي عملية بتلمس رصيد / مخزون / دفعة تُنفَّذ جوه `runTransaction`، مش writes منفصلة قابلة للتعارض
- [ ] أي عملية إرجاع (return) مرتبطة صراحة بعملية البيع الأصلية (مش مجرد رقم منفصل)
- [ ] لا يوجد سيناريو race condition واضح (عمليتين متزامنتين بيعدلوا نفس المستند)

## د. التوافق مع منهجية REQ
- [ ] `docs/backlog.md`, `known-issues.md`, `changelog.md` اتحدثوا لو مطلوب
- [ ] كل بند Acceptance Criteria في الـ REQ اتفحص فعليًا (مش "افتراض إنه شغال")
- [ ] لو REQ اتقفل بـ "accepted risk" بدل "fixed": فيه توثيق صريح للسبب في docs

## هـ. جودة عامة
- [ ] Accessibility pass لو فيه شاشة UI جديدة أو معدّلة
- [ ] مفيش منطق مكرر كان المفروض يتحط في service/hook مشترك موجود بالفعل
- [ ] النصوص العربية سليمة (لا mojibake) — خصوصًا لو فيه أي تعامل مع file encoding

- أي تعديل في منطق transaction / payment / رصيد
- أي REQ بيتقفل بحالة "accepted risk"
