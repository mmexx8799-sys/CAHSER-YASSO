# Guard Review Skill

## الغرض
مراجعة CodeRabbit-style لأي REQ قبل ما يتقفل كـ Done. الهدف: منع إعلان "READY" إلا بعد اجتياز فحوصات ميكانيكية وأمان حقيقية — مش تقييم انطباعي.

## من يشغّل هذا الـ Skill
هذا الـ Skill يجب أن يُشغَّل بواسطة موديل مختلف عن الموديل اللي كتب الكود (Muse Spark Free يراجع كود GLM 5.3 Free، أو العكس). لا تشغّل الـ Skill بنفس الموديل اللي نفّذ الـ REQ — الهدف استقلالية حقيقية، مش شكلية.

## متى يشتغل
- تلقائيًا بعد أي REQ يخلص تنفيذه، قبل إعلان Done
- يدويًا عند الطلب: `/guard-review` (فحص الـ diff الحالي فقط) أو `/guard-review --full` (فحص المشروع كامل)

## المدخلات المطلوبة
- `git diff` أو `git show --stat` للـ REQ الحالي
- ملف الـ REQ نفسه (Acceptance Criteria + allowed-files list)
- في حالة `--full`: قراءة كاملة للمشروع

## آلية العمل
1. نفّذ الفحوصات الميكانيكية أولًا (قسم أ في CHECKLIST.md). أي فشل هنا = رفض فوري، وقف ولا تكمل.
2. راجع الـ diff مقابل قائمة allowed-files بتاعة الـ REQ. أي ملف اتعدل مش في القائمة = رفض، اطلب تبرير أو تراجع.
3. طبّق فحوصات الأمان وسلامة البيانات (قسم ب، ج).
4. لو الـ diff فيه أي تعديل في: firestore.rules، منطق transaction/payment، أو REQ بيتقفل كـ "accepted risk" بدل "fixed" → **قف فورًا ولا تصدر حكم نهائي**. اكتب تقرير وحدد إن الحالة تحتاج مراجعة خارجية (Claude أو المستخدم يدويًا). لا تعطي هذه الحالات "READY".
5. اكتب تقرير مراجعة بصيغة: ✅ Passed / ❌ Failed / ⚠️ Needs external review — لكل بند في CHECKLIST.md، مع سبب محدد (سطر كود أو رسالة خطأ)، لا أحكام عامة بدون دليل.
6. لا تصدر "READY" إلا لو كل بنود قسم أ وب وج ✅، وصفر بنود ⚠️.

## قاعدة صارمة
ممنوع افتراض إن شيء "شغال" بدون تشغيل الأمر الفعلي (tsc, build, إلخ) ورؤية مخرجاته. أي ادعاء في التقرير بدون دليل مرفق (مخرجات أمر، أو رقم سطر في الكود) يُعتبر فشل في المراجعة نفسها.

## المخرج المتوقع
تقرير REPORT بالشكل:
```
## Guard Review Report — REQ-XXX
Reviewer model: [اسم الموديل]
Developer model: [اسم الموديل]

### أ. فحوصات ميكانيكية
- [✅/❌] tsc --noEmit — [دليل]
- [✅/❌] npm run build — [دليل]
...

### ب. أمان
...

### ج. سلامة البيانات
...

### حالات تحتاج مراجعة خارجية
- [قائمة أو "لا يوجد"]

### القرار النهائي
READY / NOT READY / NEEDS EXTERNAL REVIEW
```

راجع تفاصيل كل بند في `CHECKLIST.md` المرفق بجانب هذا الملف.
